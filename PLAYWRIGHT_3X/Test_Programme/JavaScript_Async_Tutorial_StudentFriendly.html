JS Async Promises

JavaScript Async Programming Tutorial

In JavaScript, some operations take time, like reading a file, calling an API, or waiting for a server response. These are called asynchronous operations. JavaScript handles them efficiently with callbacks, promises, and async/await.

1. Callback

A callback is a function passed to another function. It runs after the task is done. 

function loadData(callback) {
  setTimeout(() => {
    const result = "Data loaded";
    callback(result);
  }, 1000);
}

loadData(function (data) {
  console.log(data);
});

Example: After 1 second, the callback starts running and prints the data.

Problem: If there are many nested callbacks, code becomes messy. This is called callback hell.

2. new Promise

A Promise is a better way to handle async operations. It gives us a clean structure for success and failure. 

const myPromise = new Promise((resolve, reject) => {
  const isSuccess = true;

  setTimeout(() => {
    if (isSuccess) {
      resolve("Success!");
    } else {
      reject("Failure!");
    }
  }, 1000);
});

myPromise
  .then((value) => console.log(value))
  .catch((error) => console.log(error));

Important: A Promise has three states:

  • pending - still running
  • fulfilled - success
  • rejected - error

3. Async

The async keyword is used before a function to tell JavaScript that this function will work asynchronously. 

async function greet() {
  return "Hello";
}

greet().then((result) => {
  console.log(result);
});

Note: An async function always returns a Promise.

Even if you return a normal value, JavaScript wraps it in a Promise automatically.

4. Await

The await keyword waits for a Promise to finish before continuing the next line. 

async function fetchData() {
  const result = await new Promise((resolve) => {
    setTimeout(() => resolve("Welcome"), 2000);
  });

  console.log(result);
}

fetchData();

Why it is useful: It makes async code look cleaner and easier to read, almost like normal synchronous code.

Rule: You can use await only inside an async function.

5. Promise.all

Promise.all() runs multiple promises at the same time and waits for all of them to finish. 

const task1 = Promise.resolve("A");
const task2 = new Promise((resolve) => setTimeout(() => resolve("B"), 1000));
const task3 = new Promise((resolve) => setTimeout(() => resolve("C"), 2000));

Promise.all([task1, task2, task3]).then((values) => {
  console.log(values);
});
[ 'A', 'B', 'C' ]

Use it when: all tasks must finish before the next step.

6. Promise.race

Promise.race() returns the result of the first promise that finishes first. 

const slow = new Promise((resolve) => setTimeout(() => resolve("Slow"), 2000));
const fast = new Promise((resolve) => setTimeout(() => resolve("Fast"), 500));

Promise.race([slow, fast]).then((result) => {
  console.log(result);
});
Fast

Use it when: you want the fastest result or a timeout-style behavior.

Promise.all vs Promise.race

Promise.all
  • Waits for every promise.
  • Returns all results in order.
  • Fails if any promise fails.
Promise.race
  • Returns the first finished promise.
  • Does not wait for all.
  • Important for fast response handling.

Simple Real Example

async function getUser() {
  return new Promise((resolve) => {
    setTimeout(() => resolve("Amit"), 1000);
  });
}

async function getPosts() {
  return new Promise((resolve) => {
    setTimeout(() => resolve(["Post 1", "Post 2"]), 1500);
  });
}

async function loadHomePage() {
  const [user, posts] = await Promise.all([
    getUser(),
    getPosts()
  ]);

  console.log("User:", user);
  console.log("Posts:", posts);
}

loadHomePage();

In real web apps, many APIs are called together. We wait for all of them to finish before showing the page.

Summary

  • Callback = function called after async work finishes.
  • new Promise = create a promise for async work.
  • async = makes a function asynchronous.
  • await = waits for a promise to finish.
  • Promise.all = wait for all promises.
  • Promise.race = use the first finished promise.
Modern JavaScript prefers async/await because it is simpler and easier to read than nested callbacks.
